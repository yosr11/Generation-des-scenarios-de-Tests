📊 Node Types

Start — Pipeline entry point
Agents — LLM-driven analysis & generation
Validation — Quality checks & coverage
Gap-Fill — Correction loop
Terminal — End states (skip/no tests)
End — Pipeline completion
📌 Key Features:
• Conditional Routing: Dynamic path selection based on story type & validation results
• Feedback Loop: Gap-fill (Agent 3) + Re-validation (Agent 4) for coverage improvement
• Max Iterations: Prevents infinite loops with configurable correction limits
• Graceful Degradation: Non-blocking agents (e.g., Agent 2) don't fail the pipeline
• State Persistence: PipelineState carries all data through the workflow
🔄 Feedback Loop Details:
When Agent 4 detects issues (coverage < 70%, duplicates, ambiguities):
① Agent 3 generates gap-fill tests for uncovered points
② Tests are merged and deduplicated
③ Agent 4 re-validates the expanded test suite
④ Loop repeats until coverage ≥ 70% or max iterations reached
⑤ Agent 5 generates final report with correction history
🔗 State Transmission (Left-to-Right Flow):
START → ENRICH → CLASSIFY → ANALYSIS → BUSINESS MODEL → GENERATE → VALIDATE → [REPORT or GAP-FILL]

PipelineState contains:
• story_id, story (enriched from Jira)
• analysis (Agent 1), business_model (Agent 2)
• tests (Agent 3), validation (Agent 4), report (Agent 5)
• correction_iteration, coverage_rate, token_usage
All agents read and update this shared state ➜
